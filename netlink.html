Netlink: parts of the same file over each internet connection

Netlink downloads different parts of the same file through each internet connection you select, then assembles them on disk. It combines connections for its own downloads and requires no VPN or virtual network adapter.

No VPN, no virtual network adapter, no relay server — all on one machine. Netlink uses HTTP range requests to download parts of the same file through each internet connection in parallel; faster connections take more parts, and the parts are assembled on disk. Each part is fetched over that connection’s own public IP; websites see several IPs, not one. Torrents spread their peers across the connections.

Speed: with 5 connections at Starlink's typical (not measured) 80–200 Mbps each (Starlink published typical speeds), one big download can approach the combined ~400–1,000 Mbps (realistically 60–80% of that, ~240–800 Mbps) when the site supports range requests.

Future option: Netlink on the router

Future option: the router would run the same downloader itself (Netlink’s engine ported to a Linux service), still fetching parts of the same file through each internet connection, each with its own public IP, and assembling them on disk. No bonded or virtual IP and no tunnel. On Linux, each socket can be bound to one connection (SO_BINDTODEVICE).

What Netlink can do

  • Download parts of the same file through each internet connection on one machine, then assemble them on disk.
  • No VPN, virtual network adapter, relay or VPS needed.
  • Combine connections for its own downloads (files fetched in Netlink).

What Netlink can't do

  • Speed up browsing, streaming, calls or uploads.
  • Speed up other devices on the network.
  • Work over one connection split in five: each connection must be its own internet connection with its own public IP.
  • Speed up a single file if the site doesn't support range requests.
